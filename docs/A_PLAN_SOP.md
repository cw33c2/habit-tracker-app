# 🚀 A計畫懶人包 (A-Plan SOP) - 專案開發與防崩潰規範指南

本文件為專案的標準開發規範說明書，已整合最高規格之 AI 顧問溝通協議與終極防當機防禦機制。

---

## 📌 第一部分：AI 運作與溝通規範 (AI Behavior Protocols)

### 🤝 1. 專屬 AI 顧問溝通協議 (The Consultant Protocol)
1. **階段選擇彈出**：僅在使用者輸入 `/a-plan` 啟動或切換大階段時，強制呼叫 `ask_question` 工具彈出選單供選擇。
2. **階段開場 (提點與聆聽)**：進入具體階段內部時，AI 只能給予「重點提點」說明目標，然後立刻停下來等待使用者敘述。
3. **動態診斷 (清晰即執行)**：使用者敘述後，若需求清晰且安全，AI 直接執行，絕不廢話。
4. **危險攔截與強制追問 (防崩潰機制)**：只有當聽不懂/細節模糊，或使用者的要求會導致系統崩潰/大量 Bug 時，AI 才能強制啟動追問 (Grill-me 模式)。
5. **詳盡選項原則 (完整提示)**：一旦觸發追問或危險警告，AI 提供的選項必須給出完整、清楚、具體的方案說明與修復建議。

## 📌 第二部分：開發核心守則 (Core Safety Rules)

### 1. 🛡️ 防白屏當機與重覆 Bug 黑名單機制 (Anti-Recurrence Protocol)
- **白屏當機三秒急救箱**：
  - 全站頁面強制包裹 `<ErrorBoundary>`，發生未預期錯誤時顯示友善中文畫面，**絕對禁止出現白畫面當機 (White Screen of Death)**。
  - 發生錯誤時，AI **嚴禁憑空猜測程式碼**，必須第一時間調閱並讀取完整 Console 日誌與 Stack Trace 追蹤碼。
- **重覆失敗黑名單 (二次無效即封鎖)**：
  - 若修復後系統**再次出現一模一樣的崩潰結果（第二次發生）**，AI 必須將該修復方法列入「無效黑名單」，**絕對禁止第三次使用相同的做法或語法**。
  - AI 必須向上溯源（Trace Upstream），從資料輸入與狀態源頭進行全盤根治。
- **防當機 4 大程式碼鐵律**：
  - 1. 所有物件層級讀取必須強制使用 `data?.user?.name`。
  - 2. 所有陣列讀取必須寫成 `(list || []).map(...)`。
  - 3. 外部資料（如 LocalStorage、Google Sheets API）必須通過 `Zod Schema` 驗證與清洗。
  - 4. 所有網路 Fetch 請求必須加上 8 秒 Timeout 超時保護，避免弱網路下手機凍結。

### 2. 🔀 推送模式彈性選用 (Agile vs. Strict Push Protocol)
- **敏捷單人模式 (預設)**：若使用者追求快速預覽與迭代，AI 允許將通過驗證的變動直接 `git push` 至主分支，節省審核時間。
- **團隊企業模式**：若專案屬於團隊協作或高風險正式產品，AI 嚴禁直接推播至 main，一律建立 GitHub PR 由使用者審核。
